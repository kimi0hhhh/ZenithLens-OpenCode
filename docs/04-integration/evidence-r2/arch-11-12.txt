#### 11.3 C3 · 链重算来源标注 → **裁定：采纳（最小字段）**
- **结论**：新增 `LedgerChain.chain_source`（enum `chain_source`：`stored` / `recomputed`；null = 不可用）。价值 = 审计透明（读时重算非原始记录，标注防误读）；成本 = 1 字段。
- **口径**：`recomputed` = 读时按**写入同源口径**（bars[:t-1]、H=1、六步含 `exit_threshold=0.5200`）重算；`stored` = 写入时缓存的链（BLOCK-A3 可选优化启用后的新行）；`chain_available=false` → `chain_source=null` + `chain=[]`。
- **范围注**：本字段经架构批准，为 BLOCK-A3「不新增字段」约束的**唯一豁免**；其余 BLOCK-A3 约束不变。
- **契约**：`09-r2` 升 **v9.3**（§11 注记，仅此 1 字段 + 1 枚举；C1/C2 不改契约）。
- **落地**：随 BLOCK-A3 backend 修复一并实现；前端可在时间线 tooltip 显示来源（可选）；QA 断言：available 行 `chain_source ∈ {stored, recomputed}`，unavailable 行 null + 空链。

#### 12.1 F-6 · 方法名与 top_n=20 名实不符 → **裁定 ②：维持 `eastmoney_f10_top10_weighted` + 语义注记（不改名）**
- **结论**：方法名**维持不变**（冻结）；契约 §3.3 追加语义注记：「`eastmoney_f10_top10_weighted` 为**历史标识**（v8 首版口径为前十）；v9 起实际档位由 `top_n` 字段承担（10/20），方法名冻结；改名须版本 +1 并评估历史记录兼容」。**前后端零代码改动**。
- **理由（四条）**：
  1. **历史记录兼容（决定性）**：`valuation_history.jsonl`（INSERT-ONLY）与既有 trace 明细已落大量携带该字符串的记录；改名将产生「同一方法两种标识」的审计混合，违背「同一概念一个词」的术语纪律——语义注记零成本消除误解且保持全史单标识。
  2. **字面量共用上下文**：同一字符串在**持仓穿透**（`PenetrationTrace.method` / `penetration_method`，真实为 top10 口径）中继续使用；改名会在相邻语义中产生两个近似字符串（`..._top10_weighted` vs `..._weighted`），反增混淆面。
  3. **既定设计**：契约 v9 §3.3 已确立「method 名不变 + `top_n` 承担档位」的设计（V18 收编时即如此）；档位事实由 `top_n` 如实给出，审计可判——名实关系已由字段兜底。
  4. **轮次纪律**：R2/S5 处于缺陷关闭期；改名需契约 +1 + 后端 + 测试 + 双边同步 + G-BE-02 重跑，收益（消除轻微历史名）与成本不匹配；「不为以后可能加抽象」。
- **同步点清单（②下的动作，均为确认级）**：
