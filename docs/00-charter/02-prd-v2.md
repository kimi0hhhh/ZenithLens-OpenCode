## 摘要

1. 本 PRD 定义 **17 个功能点**（F-01..F-17）+ **40 项特调组件需求**（R-UI-01..40，全部 P0），实现 Brief §8 的 P0 最小闭环：**持仓 + 实时估值 + 信号/预测 + 复盘**，外加启动可靠性与离线底线。
2. 两条命脉写死在本文：**实时估值五档降级**（F-02/F-03/F-04，来源徽章由后端驱动、估值≠净值）与**预测核心逻辑**（F-06：E1/E3 门 → DDSM → 双否决 → 出口 P>0.52，基线 `max(恒涨,恒跌)` 报 Δ）。
3. 每个数字都可追溯到后端字段或口径；前端**禁止自造数据**，取不到就显示"未知"。
4. **不做清单 12 条**，其中 7 条直接来自 Brief §7/§5.5，用于防止范围蔓延。
5. 验收标准全部可测量（含时间阈值、字段名、误差上限）。
6. **v2 核心**：R-UI-01..40 与 Brief §9 的 40 项**一一对应、不得简化或删除**；每项含"组件名 / 所属页 / 输入-处理-输出-异常 / 验收标准 / P0"。承接上一版线框丢失 legacy v2 壳 83% 特调内容的教训（Brief §9 引言）。

## 正文

### 0. 术语与口径（全局）

| 术语 | 定义 | 来源 |
|---|---|---|
| 净值 | 基金公司公布的官方单位净值（盘后回填） | Brief §3.2 |
| 估值 | 系统对"今日净值"的预估值，可能来自官方/估算/重仓/代理 | Brief §3.2 |
| 五档降级链 | official → intraday → holdings → proxy → unknown | Brief §3.2 |
| 开口 | 某资产当日满足触发门且通过 DDSM 与双否决、出口 P>0.52，产出"涨"信号 | Brief §5.1 |
| 灰/不表态 | 未开口资产；加权时从分子分母同时剔除，**不是 0.5** | Brief §5.2（组合规则） |
| 基线 | 同期 `max(恒涨率, 恒跌率)`，成绩以增量 Δ 呈现 | Brief §4、§5.1 |
| 覆盖档位 | A 已接入 / B 代理已验证 / C 代理待验证 / D 暴露待定 | Brief §8 |
| 未知 | 无任何可信估值来源；**与持平 0.00% 视觉与语义都必须区分** | Brief §5.4 |

**全局铁律（下称"三铁律"）**：
1. **不造假**：前端展示的每个数字必须来自后端；取不到渲染"未知"，禁止用 0 或占位值冒充。
2. **不夸大**：任何预测成绩必须与基线并列、报 Δ；跑不赢基线就灰显。
3. **不误导**：估值≠净值，来源必须可区分；未知≠持平；"明日涨"不得暗示当天可买。

### 2. 核心功能详述

#### F-01 · 组合总览（P0）

- **输入**：持仓列表（每只含份额/成本/最新净值或估值）；估值来源档位。
- **处理**：`总资产 = Σ(份额 × 最新估值)`；`累计收益 = 总资产 − Σ成本`；`收益率 = 累计收益 / Σ成本`；`今日预估盈亏 = Σ(市值 − 市值/(1+pct))`，仅对**有可信估值**的持仓求和，未知持仓从分子分母同时剔除。
- **输出**：四张汇总卡——总资产（元，2 位小数，千分位）、今日预估盈亏（带 +/− 号与涨红跌绿）、累计收益、收益率（百分比，2 位小数）；每卡附口径副标题与"覆盖 N/M 只"。
- **异常**：成本合计为 0 → 收益率显示"—"而非除零；全部未知 → 今日盈亏显示"未知"；部分未知 → 副标题红字标注"仅覆盖 N/M 只，其余不计入"。

**验收**：
- [ ] 首屏渲染完成 ≤ 2.0s（本机、22 只持仓）后一屏可见 4 个数字。
- [ ] 总资产与明细逐行求和误差 = 0（金额口径统一为 2 位小数）。
- [ ] 存在未知持仓时，副标题出现"仅覆盖 N/M 只"且 N<M。

#### F-02 · 实时估值五档降级（P0 · 核心）

- **输入**：基金代码；官方净值接口（当日是否已公布）；实时行情源（腾讯/天天基金/新浪）；重仓股列表及当日涨跌；代理 ETF 映射及当日涨跌；官方最新已公布净值。
- **处理**：按固定优先序尝试，命中即停，并记录来源：

  | 档 | mode | 取数逻辑 |
  |---|---|---|
  | 1 | `official` | 官方当日净值已公布 → 直接用官方涨跌 |
  | 2 | `intraday` | 官方未出 → 行情源的盘中估算净值 |
  | 3 | `holdings` | 官方未出 → 前十大重仓股当日涨跌加权 |
  | 4 | `proxy` | 官方未出 → 代理 ETF 当日涨跌 × 官方最新净值 |
  | 5 | `unknown` | 以上全部失败/回测证明无信息量 → 只标净值截止日，不冒充今日 |

- **输出**：每只基金一个估值对象：`{ mode, pct, source_label, trace, nav_date, conf }`；`pct` 单元为百分比；`nav_date` 为所用净值的截止日。
- **异常**：接口超时/返回空/解析失败 → 逐档下探；五档全失败 → `mode=unknown` 且 `pct=null`；代理缺失 → 不得用其他代理替代（宁可 unknown）；估算历史 MAE 已知偏大（> 行业基准 0.8%）时 `conf` 标低。

**验收**：
- [ ] 任意持仓行的来源徽章 = 后端 `mode` 字段（逐行一致，无静态硬编码）。
- [ ] `mode=unknown` 行的 `pct` 必须为 null，界面不得出现该行今日涨跌数值。
- [ ] 同一基金同日只出现一个 mode；`trace` 可列出尝试过的档位顺序。
- [ ] `official` 回填当日净值后，当日已入账估值记录的 mode 不被改写（可新增净值字段，不可覆盖来源）。

#### F-03 · 估值来源徽章与降级链路（P0 · 核心）

- **输入**：F-02 输出的 `mode / source_label / trace / conf / nav_date`。
- **处理**：按 mode 映射徽章文案（official=官方净值 / intraday=盘中估算 / holdings=重仓加权 / proxy=代理近似 / unknown=未知）；按回测 MAE 决定置信度配色（高/中/低/无）。
- **输出**：行内徽章（短文案）+ 悬浮/展开详情（来源说明、降级链路、历史 MAE、方向命中率、样本日数）。
- **异常**：`trace` 缺失 → 徽章只显示 mode 文案，不显示链路（不编造链路）；`nav_date` 缺失 → 显示"净值截止日未知"。

**验收**：
- [ ] 五档 mode 各有独立徽章文案，同一屏内可区分。
- [ ] 详情可显示降级链路字符串（如 `official 未出 → intraday 命中`）。
- [ ] 官方净值与估算在同一行时，通过徽章可一眼区分"哪个是既成事实、哪个是估算"（对应 Brief §5.4「估值来源徽章」）。

#### F-04 · 未知态渲染（P0 · 核心）

- **输入**：`pct` 可能为 null 或数值。
- **处理**：`pct === null || undefined` → 涨跌列渲染「未知」（斜体灰）、今日盈亏列渲染「—」；`pct === 0` 才渲染 `+0.00%`。
- **输出**：涨跌单元格、今日盈亏单元格、汇总口径副标题。
- **异常**：`pct` 为字符串/NaN → 一律按未知处理，禁止 `Number(null)=0` 之类隐式转换。

**验收**：
- [ ] 当 `pct` 为空，界面**绝不出现** `+0.00%`（自动化断言：未知行文本不含 `+0.00%`）。
- [ ] 全量未知时，今日盈亏卡显示「未知」，不显示 `+0.00`。

#### F-05 · 覆盖度分级 A/B/C/D（P0）

- **输入**：每只基金的档位（A/B/C/D）与依据说明、市值。
- **处理**：按档位分组，计算每组只数、市值合计、占总市值比例。
- **输出**：四档分级面板；明细行显示档位字母；信号列按档位显示"涨/灰/待验证/暴露待定"。
- **异常**：档位未知 → 归入 D 并标注"档位未定"；市值合计为 0 → 占比显示"—"。

**验收**：
- [ ] 四档面板各显示只数、市值、占比三个数字。
- [ ] C/D 档在信号列显示「待验证」/「暴露待定」，**不得**显示「涨」。
- [ ] 组合加权（F-08）只纳入 A/B 档（可断言 C/D 不在加权集合内）。

#### F-06 · 单只方向预测（P0 · 核心）

- **输入**：目标资产日线 OHLCV（量价）；代理 ETF 日线（不复权 + 自修除权：>25% 跳变缩放历史）；训练段统计量（分位断点、IC 符号、涨率）。
- **处理**（严格按 Brief §5.1，不得 OR 合并已证伪项）：

  1. **触发门**（二者任一，且仅 E1/E3）：
     - E1 跳空：`low[t] > high[t-1]`
     - E3 无量急跌：`ret < -2%` 且 `vr < 0.8`
     - **E2/E4 已证伪，禁止并入**（不做 OR 合并）。
  2. **DDSM**：三维 `[r2, om, vr]` 各按训练段分位切 5 档 = **125 状态格**；训练每样本加噪 `K=4`、每维以 `p=0.25` 概率扰动 ±1 档；**收缩** `P = (n_up + 10 × 训练段涨率) / (n + 10)`；样本不足 `MIN_N=15` 的格不单独出值，向全局基准收缩。
  3. **双否决**：
     - 拥挤度：六维（mom5/vr/dev/vpcorr/volat/skew）按训练段 IC 符号等权复合 z；处训练段**最拥挤 40%** → 否决。
     - KLOW2：下影线占振幅比 `(min(open,close)−low)/(high−low)` 处**最不利 40%** → 否决。
  4. **出口**：`P > 0.5 + BAND(0.02) = 0.52` 且无否决 → 输出"涨"；否则"灰（不表态）"；**永不做空**。
  5. **多窗口**：T+1 走完整链（门+DDSM+双否决）；T+3 走"仅触发做多"；T+15 走"门+DDSM"（按 Brief §5.1 与设计基准定式）。

- **输出**：`{ code, gate, p_up, ddsm_state[3], veto_crowd, veto_klow2, signal(涨|灰|弃权), windows{T1,T3,T15} }`。
- **异常**：日线缺失/不足回看窗口 → 不开口，`signal=灰` 且标注原因；代理映射缺失（C/D 档）→ 显示"待验证/暴露待定"，不参与加权；P 计算结果为 NaN → 按灰处理并记日志。

**验收**：
- [ ] 信号必附 `gate / p_up / 否决层状态` 三者，缺一视为不合格展示。
- [ ] `p_up ≤ 0.52` 时**绝不**输出"涨"（可自动化断言）。
- [ ] 任一否决亮灯 → 输出"弃权"，且展示是哪个否决。
- [ ] 界面无任何"做空/卖空"入口或文案。
- [ ] E2/E4 不出现在任何触发门文案中。

#### F-07 · 信号链路解释（6 步）（P0）

- **输入**：F-06 各步中间量。
- **处理**：按固定 6 步组装：①触发门 ②DDSM 档位 ③拥挤度否决 ④KLOW2 否决 ⑤出口判定 ⑥输出。
- **输出**：可展开的时间线/链路，每步含标题、状态（亮灯/未亮灯/通过）、关键数值。
- **异常**：某步无数据 → 该步显示"数据缺失"而非留空；不得省略步骤。

**验收**：
- [ ] 展开后 6 步齐全。
- [ ] 每步至少一个具体数值（E3 示例：`ret −3.82%`、`量比 0.72`、`P=0.61`、`z 分位`、`下影线比`）。
- [ ] 出口步明确显示阈值 `0.52`。

#### F-08 · 组合三窗口加权预测（P0 · 核心）

- **输入**：各开口资产的市值与 P；各资产档位。
- **处理**（三条规则缺一不可）：
  1. **只有开口仓位计入权重**——灰的从分子分母同时剔除，不按 0.5 计。
  2. **C/D 档不参与**加权。
  3. 结果必须附**覆盖市值占比**。
- **输出**：T+1 / T+3 / T+15 三张窗口卡：组合加权 P（百分比 1 位小数）、覆盖市值占比（百分比 1 位小数）、覆盖金额。
- **异常**：无任何开口 → P 显示"—"、文案"今日无开口"；覆盖占比为 0 → 不显示 0.0% 的"看涨"结论。

**验收**：
- [ ] 每窗口同时显示「加权 P」与「覆盖市值占比」。
- [ ] 覆盖 < 100% 时显式写出"其余 X% 不表态"。
- [ ] C/D 档不计入加权（可断言）。
- [ ] 灰仓位不产生 0.5 的贡献（加权分母 = 开口市值）。

#### F-09 · 审计台账（INSERT-ONLY + 回填）（P0）

- **输入**：收盘时点各开口记录；到期后的实际涨跌。
- **处理**：开口即写入一条不可变记录；到期只回填 `t1_real/t3_real/t15_real`，其余字段不改。
- **输出**：台账列表/时间线，字段：`date / code / gate / p_up / ddsm_state / veto_crowd / veto_klow2 / signal / t1_real / t3_real / t15_real / cost_est`。
- **异常**：重复写入（同日同 code）→ 拒绝并提示"已存在"；回填时标的不存在 → 记录为空，不回滚已写内容；无到期数据 → 字段显示"—"。

**验收**：
- [ ] 界面无"编辑台账/删除台账"入口。
- [ ] 同日同 code 不可重复写入（可断言唯一性）。
- [ ] 回填只影响 `t*_real`，`signal` 等原始字段保持写入时值。
- [ ] 时间线按日期倒序。

#### F-10 · 复盘成绩 vs 基线（P0）

- **输入**：回测/实盘统计（命中率、开口数）；同期基线 `max(恒涨,恒跌)`。
- **处理**：`Δ = 命中率 − 基线`；成绩必须来自走前时序 CV（purge gap = H+2，冻结 holdout 60 日）。三窗口分别展示。
- **输出**：成绩表：`窗口 / 定式 / 命中率 / 开口 / 基线 / Δ`；Δ 按正负着色（涨红/跌绿）。
- **异常**：基线未算出 → 该窗口 Δ 显示"待填充"；实盘台账不足 → 实盘对照显示"影子盘未启动/样本不足"，不回退用回测数字冒充实盘。

**验收**：
- [ ] 同时显示命中率、基线、开口、Δ 四列。
- [ ] Δ 旁/悬浮标注基线口径与 CV 口径（"走前 CV · purge=H+2"）。
- [ ] 基线缺失时显示"待填充"，**不得填估计值**。
- [ ] 回测与实盘对照在视觉与文案上必须可区分。

#### F-11 · 启动与部署可靠性（P0）

- **输入**：启动命令 / exe 点击事件；端口配置。
- **处理**：在 Python 3.8+ 环境直接起服；绑定本机 `127.0.0.1`；exe 点击"启动"拉起本地服务并给反馈。
- **输出**：可访问的 `http://127.0.0.1:<port>`；exe 出现窗口或明确错误提示。
- **异常**：端口占用 → 自动换端口或提示；Python 版本/依赖缺失 → 给出可读错误（不得静默退出）；服务起不来 → exe 显示错误，不得无反应。

**验收**：
- [ ] Python 3.8 环境执行 `python app.py` 可成功起服并访问（实测）。
- [ ] exe 点击"启动"后 ≤10s 出现窗口或明确错误提示。
- [ ] 启动失败日志含可读原因（非堆栈裸抛）。
- [ ] 未发生外部上传（除行情/估值取数）。

#### F-12 · 隐私打码（P1）

- **输入**：隐私开关状态。
- **处理**：开关开启时，所有金额字段渲染为 `••••`；占比/百分比涨跌照常。
- **输出**：总资产、今日盈亏、累计收益、持仓金额、成本全部打码。
- **异常**：开关状态存储失败 → 默认"不打码"并在下次启动提示；打码只影响展示，不影响计算与导出口径。

**验收**：
- [ ] 开启后所有金额位显示 `••••`，占比与涨跌百分比可见。
- [ ] 刷新后状态保持（本地记忆）。
- [ ] 打码不影响任何计算数字（内部数值不变）。

#### F-13 · 三窗口口径与执行路径说明（P1）

- **输入**：T+1 定义、场外基金申购截止时间与信号生成时间。
- **处理**：生成可展开说明：`up=1 若 close[T+1] > close[T]`；三条执行路径 A 新建仓位 / B 已持有仓位 / C 场内 ETF。
- **输出**：口径卡 + 三路径对比卡 + 结论（对场外基金最现实用法是 B）。
- **异常**：无。

**验收**：
- [ ] 明文写出 `close[T+1] > close[T]` 定义。
- [ ] 明确"场外基金 15:00 截止、信号 15:30 才出"的时序坑。
- [ ] 结论指向 B（持有/赎回决策），无"当天可买入"暗示。

#### F-14 · 因子治理（P1）

- **输入**：因子清单及其角色/牌照/六窗表现/寿命状态。
- **处理**：分四盘（正式/淘汰影子/有效因子影子/冷冻）、四本账本、评分链（lift→悬崖查表→窗权重→准入度→加总）、生命周期规则。
- **输出**：盘面、账本用途与最近记录、评分链说明、生命周期规则文本。
- **异常**：某账本无记录 → 显示"待写入"；评分数据缺失 → 显示"—"。

**验收**：
- [ ] 四个盘面各含因子及角色。
- [ ] 至少 4 本账本的用途与示例可见。
- [ ] 评分链悬崖规则与窗权重（8/22/15/10/30/15）可见。

#### F-15 · 引擎观测台（P1）

- **输入**：引擎运行状态、台账状态、DDSM 状态表、冻结参数、六维特征快照。
- **处理**：只读聚合展示。
- **输出**：HUD 卡、影子盘台账状态与最近记录、训练状态、冻结参数、六维输入（DDSM 三维 + 拥挤度六维）。
- **异常**：引擎未运行 → HUD 显示"离线"并给出最近成功时间；无快照 → 显示"暂无数据"。

**验收**：
- [ ] HUD 显示运行状态与最近更新时间。
- [ ] 冻结参数 `K=4 / p=0.25 / MIN_N=15 / SHRINK=10 / BAND=0.02` 可见且标注"改动须重走六关"。
- [ ] 本页只读，无编辑/下发参数入口。

#### F-16 · 数据源健康（P1）

- **输入**：各数据源连通探测结果、最近成功时间、失败次数。
- **处理**：三态判定（正常/不通/波动）。
- **输出**：数据源列表 + 状态徽章 + 时间戳 + 失败次数。
- **异常**：探测未执行 → 显示"未检测"；不通常见 → 首页降级提示条。

**验收**：
- [ ] 每个数据源显示三态之一 + 最近时间戳。
- [ ] 至少覆盖腾讯日K/腾讯实时/天天基金/新浪。
- [ ] 不通时首页出现降级提示条。

#### F-17 · LLM 事件编码器（shadow，P2）

- **处理**：仅做事件编码（温度 0、短结构化输出）；输出须先过四关回测才可进生产。

- **异常**：编码波动/失败 → 记录失败次数，不阻塞预测主链；未过回测 → 不得出现在信号链。

**验收**：
- [ ] 界面标注"仅用于事件编码，不做最终预测 / 当前 shadow 观察区"。
- [ ] 温度与输出格式硬约束可见。
- [ ] 事件维未过回测前不在信号链出现。

### 4. 不做清单（本版明确不做）

> 这一栏比功能清单更能决定能否按时交付。以下 12 条经用户 Brief §7/§5.5 确认。

1. **不做多用户**：无注册/登录/权限体系，只服务单用户本机。
2. **不做云端同步**：无服务器、无账号、无跨设备同步。
3. **不做实盘交易**：不接入券商/基金交易接口，只给判断依据，不下单。
4. **不做做空**：预测只做多，永不做空，界面无任何做空方向。
5. **不做随机切分回测**：一律走前时序 CV，禁随机切分（Brief §5.2）。
6. **不接已证伪的事件维进生产**：E2/E4 门、事件维接入 DDSM、宽基/黄金/纳指境内方向模型、gini 树/GBDT、naive 特征拼接/概率平均融合、loss-guided/IC 自适应加噪 —— 均不重复投入（Brief §5.5）。
7. **不做移动端 App**：只做本地 web + 桌面 exe。
8. **不做自动交易信号推送**：不接短信/微信/邮件推送，只在本机看。
9. **不做持仓穿透/RBSA 的完整实现（本版）**：C/D 档先诚实标注"待验证/暴露待定"，不硬上（Brief §8 覆盖度扩展放 P1 之后）。
10. **不做 LLM 参与最终预测**：LLM 仅事件编码，且停在 shadow（Brief §5.5）。
11. **不做历史净值的全量本地重算**：只按需拉取与缓存，不做全市场历史回补。
12. **不做基金数据的人工纠错编辑器**：持仓读 `app_data/funds_data.json`，前端不提供改写原始数据源的能力（只提供产品内增删改持仓）。
