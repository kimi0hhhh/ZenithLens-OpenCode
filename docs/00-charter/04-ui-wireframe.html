T+1 到底预测的是什么R-UI-10 · 口径定义 · 三条执行路径 · 点开查看
up = 1　若　close[T+1] > close[T]
是"明日收盘价 vs 今日收盘价"，不是"明日收盘 vs 明日开盘"。信号在 T 日 15:30 收盘后生成， 预测 T+1 日收盘相对 T 日收盘的涨跌方向。

时序坑：场外基金申购截止 15:00，而信号 15:30 才出 —— 当天按 close[T] 成交的窗口已经关了。
A · 新建仓位
T+1 申购按 close[T+1] 成交，吃的是 close[T+2]−close[T+1]，晚了一拍
B · 已持有仓位
看到"明日涨"→ 决定不在 T+1 赎回 这条可执行
C · 场内 ETF
T+1 开→收，吃 open→close，口径仍不同
结论：对场外基金最现实的用法是 B（持有/赎回决策），不是 A（择时建仓）。

右边做了什么：①加噪增强（每样本 K=4 副本、每维 p=0.25 扰动 ±1 档、副本沿用原标签）＝状态空间平滑正则化；②收缩 P=(n_up+10×涨率)/(n+10)，小样本格向全局基准收缩。实测加噪后 +1.6~5.5pp，覆盖率提升 7~60 倍。
已证伪：loss-guided（−2pp）、IC 自适应加噪、K=8 过度稀释 —— 均匀加噪 + 强收缩就是小状态空间的最优解。

LLM 接口 R-UI-33 · 仅用于事件编码，不做最终预测

本地存储，不上传、不进日志、不写进任何产物
当前状态：shadow 观察区。温度固定 0、输出纯 JSON。
三条硬约束（都是踩过的坑）：
① 温度必须为 0，输出必须是纯 JSON 且禁止解释文字。实测同一条新闻跑 100 次情感分 0.40~0.80，会跨越"持有/买入"两个决策区；温度 0 也消不掉波动，只能靠结构化短输出压缩。
② 不问"利好还是利空"，改问"是否超出市场预期"。前者主观且已被定价；后者常是新闻里的客观表述，可关键词提取、一致性 100%。
③ LLM 编码输出本身必须先过四关回测才能进生产。实测事件维 IC 随 horizon 上升（T+1 +0.025 → T+15 +0.067），但接入 DDSM 三窗口均无增量（−1.5 / −0.4 / +0.0pp）——价格已 price-in。

发现的问题：存在两份 funds_data.json，且不同步。
基金监控/funds_data.json 停在 2026-08-21；基金监控/app_data/funds_data.json 停在 2026-08-24（多一条净值）。 本产品读的是 app_data 那份（较新）。差异不只是天数——018957 在旧文件里 08-21 的 pend_gz=4.6251，在新文件里同一天的实际净值是 4.5912，差 0.73%。旧文件存的是当时对当日的盘中估算，新文件是后来回填的官方净值。
这正是「估值来源徽章」必须存在的原因：估算和净值长得一模一样，不标注就会把估算当成既成事实。
建议：产品只读 app_data/ 那份，并在启动时做一次两文件一致性校验，不一致即告警。此处数字以启动时实际校验结果为准，不得硬编码。
