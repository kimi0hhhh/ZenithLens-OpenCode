T+1 到底预测的是什么口径定义 · 三条执行路径 · 点开查看
up = 1　若　close[T+1] > close[T]
是"明日收盘价 vs 今日收盘价"，不是"明日收盘 vs 明日开盘"。信号在 T 日 15:30 收盘后生成，预测 T+1 日收盘时点相对 T 日收盘的涨跌方向，持仓期恰好一个完整交易日。

但这里有个时序坑，必须讲清楚：你的持仓是场外基金，申购截止 15:00，而信号 15:30 才出来。信号落地时，当天按 close[T] 成交的窗口已经关了。所以：
A · 新建仓位
T 日 15:30 信号 → 最早 T+1 日 15:00 前申购，按 close[T+1] 成交 → T+2 赎回
吃的是 close[T+2]−close[T+1]，晚了整整一拍，不是信号预测的那一段
B · 已持有仓位
T 日 15:30 看到"明日涨" → 决定 不在 T+1 赎回，继续持有一天
这条可执行 —— 赎回也是按 T+1 净值成交，信号赶得上
C · 场内 ETF
T 日 15:30 信号 → T+1 开盘买入 → T+1 收盘卖出
吃的是 open→close，仍与 close[T]→close[T+1] 口径不同
结论：这个信号对场外基金最现实的用法是 B（持有/赎回决策），不是 A（择时建仓）。做产品时不能让"明日涨 58%"暗示你可以当天买进——那会误导。真正的解法是等 P0.5 影子盘跑起来后，实测"按信号持有 vs 不按信号持有"的差，用真实台账说话。

P<0.45 看跌 0.45–0.52 中性 0.52–0.58 弱看涨 >0.58 强看涨 无样本 横轴 = om 档（σ归一动量）· 纵轴 = r2 档（2日累计收益）
左边为什么会烂：125 个状态格里，边缘格样本极少甚至为零。n=0 时该格根本没有估计值；n=1 时 P 直接跳到 0 或 1。这就是高维离散的稀疏诅咒 —— 实测不加噪版本 Δ−3.9%，开口仅 359 天。
右边做了什么：①加噪增强 —— 每样本生成 K=4 个副本，每维以 p=0.25 概率扰动 ±1 档，副本沿用原标签，等于把孤立状态连到邻域（状态空间平滑正则化）；②收缩 —— P = (n_up + 10×训练段涨率) / (n + 10)，样本少的格向全局基准收缩，防小样本虚高。实测加噪后 +1.6~5.5pp，覆盖率提升 7~60 倍。
外部佐证：DiffsFormer（arXiv 2402.06656）独立验证了同族结论 —— 编辑式加噪优于从纯噪声生成、中等扰动强度最优。已证伪的“聪明加噪”：loss-guided（−2pp）、IC 自适应（失败）、K=8 过度稀释 —— 均匀加噪 + 强收缩就是小状态空间的最优解。

② 不问"利好还是利空"，改问"是否超出市场预期"。前者主观且已被定价；后者常是新闻里的客观表述，可关键词提取、一致性 100%。
③ LLM 编码输出本身必须先过四关回测才能进生产。实测事件维 IC 随 horizon 上升（T+1 +0.025 → T+15 +0.067），但接入 DDSM 三窗口均无增量（−1.5 / −0.4 / +0.0pp）——价格已 price-in。
当前状态：编码器已实现（prompt 固化 + 温度 0 + JSON schema），但历史事件语料不足，编码器准入考试（500 条人工标注）未完成，停在 shadow / 观察区。

本原型读的是 app_data 那份（较新）。差异不只是天数——018957 在旧文件里 08-21 的 pend_gz=4.6251，在新文件里同一天的实际净值是 4.5912，差 0.73%。旧文件存的是当时对当日的盘中估算，新文件是后来回填的官方净值。
这正是「估值来源徽章」必须存在的原因：估算和净值长得一模一样，不标注就会把估算当成既成事实。
建议：产品只读 app_data/ 那份，并在启动时做一次两文件一致性校验，不一致即告警。
