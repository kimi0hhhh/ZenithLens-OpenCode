# R2 升级需求挖掘报告 · 极境 ZenithLens

> 本文件是 **R2 升级轮的增量需求报告**，不推翻 R1 基线（`01-requirements.md` v2 原样保留为历史对照）。
> 全部现状数字来自 `docs/00-charter/00-dissection-v3.md`（2026-09-12 只读实测），逐条标注来源章节；
> 设计基准：`00-design-reference-legacy-v2.html`；配套：`02-prd-v3.md` / `03-ui-design-v3.md` / `04-ui-wireframe-v3.html`。
> 每条需求 = `[场景] → [痛点] → [需求] → [验收]`；验收全部锚定「解剖基线值 → R2 目标值」。

## 摘要

1. R2 只做五件事：把「估值更准 / 覆盖更多 / 准确率更高 / 来源更可靠」四个目标从堵点变出数，外加用户点名的**前端样式交互升级**。
2. 四目标各有一个第一堵点：**置信度 22/22 全 unknown**（§A4-1）；**C 档 7 只零验证结论**（§B2）；**T+1 Δ 无值**（backfill 0 行 + 复盘页硬编码 null，§C1）；**桌面数据根断链 + nav_history 滞后 18 天**（§D2）。
3. 本报告收敛 **25 条升级需求**（R2-01..R2-25）：P0 = 12 条、P1 = 12 条、P2 = 1 条；每条含场景/痛点/需求/验收，验收引用解剖基线值并给出 R2 目标值。
4. 解剖报告 A–G 七节 35 条建议 + 8 项风险 + 9 项技术债**逐条给出处置**（修 / 不修 / 延后，见 §3、§4），不允许「都挺重要」。
5. **覆盖口径决策**：15/22 之外的 C 档 7 只，验收硬指标 = **7/7 出验证结论**；覆盖终值 =（15 + 升 B 只数）/22 **按实计**，不承诺 22/22（详见 §7）。

### A 组 · 实时估值更准（对应解剖 §A）

#### R2-01 · 置信度误差通道（mode|code 打通）
- **优先级**：P0
- **场景**：用户打开持仓页，每行都有「官方净值/盘中估算/重仓加权/代理近似」徽章，但徽章全站灰、悬浮无 MAE——不知道现在这个数字准不准。
- **痛点**：误差通道只对 proxy 档算过（accuracy.json 只有 `proxy|code` 键）；当前 22 只走 official/holdings 档 → **22/22 confidence=unknown、mae_rate=null**，估值精度汇总条无市值加权 MAE 可显示（§A4-1 实测）。
- **需求**：为 official / holdings / proxy 档建立统一误差通道——当日估值入账后，T+1 官方净值公布时按 `mode|code` 回算当日误差、逐日累计 MAE 与方向命中率，接进徽章与汇总条；无法计算时必须显示原因（联动 R2-20）。
- **验收**：① 净值回补接通后 24h 内产生当日误差记录（按 `mode|code` 键）；② 置信度显示由 **0/22 → ≥21/22 非 unknown**（允许的 unknown 情形必须带原因标注）；③ vsum 市值加权 MAE 由 **null → 非 null** 且可逐只复算；④ 样本 n_test 逐日累计，滚动 40 日窗口；⑤ 下钻可见「MAE / n / 方向命中率 / 回测窗」四字段。
- **来源**：§A4-1、§A5-1。

#### R2-02 · 重仓加权升级（前十 → 前二十 + 港美股纳入）
- **优先级**：P1
- **场景**：主动基金 5 只（025500/018957/021528/013566/014320）官方净值未出时走前十重仓加权。
- **痛点**：F10 前十权重合计通常仅 40–60% 净值；季报披露滞后一个季度；港股/美股标的被剔除（day_change=null）放大缺口（§A4-2）。
- **需求**：重仓加权升级为**前二十大**（F10 topline=20）；港股/美股标的纳入实时源（腾讯港股行情已支持，前端只过滤了非 6 位 A 股代码）；季报披露滞后在徽章 tooltip 明示（披露截止日 + 覆盖权重）。
- **验收**：① 持仓 tooltip 显示「披露截止日 + 前二十覆盖权重」；② 港/美股纳入后 5 只主动基金的单只覆盖权重较升级前提升（目标 ≥+10pp，或出「不可得原因」结论）；③ 5 只 holdings 档在 R2-01 通道下 40 日窗首测 MAE ≤0.80%，超标进入 R2-04 复核；④ 保持「weight 或 day_change 为 null 即剔除、不编造」纪律（可断言）。
- **来源**：§A4-2、§A5-2。

#### R2-03 · QDII 跨市场时差校正
- **优先级**：P1
- **场景**：QDII（024239 纳指代理、457001/021662 恒生代理等）境内 ETF 价格 T+0 反映隔夜美股，领先净值 1–2 天（Brief §5.3 信息优势）。
- **痛点**：估值用「境内 ETF 当日涨跌」单段代理，未利用领先时差 → 024239 MAE **2.19%**、457001/021662 **1.23%**（§A3）。
- **需求**：对 QDII 采用「境内 ETF T 日收盘 + 隔夜修正」双段估算（具体算法留 S2 架构裁定）；校正口径在徽章 tooltip 明示。
- **验收**：① 40 日窗 MAE：024239 **≤1.50%**（基线 2.19%）、457001/021662 **≤1.00%**（基线 1.23%）；② 若双段法首测不达标，必须出「回退单段 + 明示原因」结论，不允许静默保留；③ QDII 行 tooltip 显示校正口径；④ 校正不改变「永不做空」与出口纪律。
- **来源**：§A4-3、§A5-3；Brief §5.3。

#### R2-04 · 代理复核批次（9 只超标逐一结论）
- **优先级**：P1
- **场景**：用户审计发现 9 只代理 MAE 超行业基准 0.8%，其中 3 只方向命中率 <60%（比抛硬币还差）。
- **痛点**：025857（电力）、163208（油气）方向命中率 **42.86%**，仍以 B/C 档在用；「覆盖 22/22」里藏着近半数精度不合格的代理（§A4-4）。
- **需求**：对 9 只超标代理（025500/024239/025857/457001/163208/014320/016665/012922/021662）逐一走前验证出结论：**保留 / 换代理 / 明示降档**；方向命中率 <60% 的三只（025857/163208/014320）必须换代理或降档不开口。
- **验收**：① **9/9 出结论**并落盘（附六窗 lift、MAE、方向命中率、样本数证据）；② 025857/163208/014320 在 R2 结束时**不得处于「超标且无结论」状态**（换代理后方向命中率 ≥60%，或降档不出信号）；③ 降档回填 tier_reason 且在覆盖面板可见。
- **来源**：§A4-4、§A5-4。

#### R2-05 · 估值历史跨日留存（≥40 交易日滚动）
- **优先级**：P0
- **场景**：用户想核对「过去 40 个交易日，估值偏差是偶发还是系统性」。
- **痛点**：valuation_history 只有 2026-09-12 **一天**（968 行全为同日多轮刷新），无法做跨日 MAE 审计（§A2、§A5-5）。
- **需求**：每日收盘后自动留档当日估值快照（按 `mode|code` 收敛），滚动保留 ≥40 个交易日，支撑跨日 MAE 与「估值 vs 净值」偏差审计。
- **验收**：① R2 上线后每个交易日产生 1 个快照日；② 可查询滚动 ≥40 日（不足时按实计并显示「累计 X/40 日」）；③ 跨日报表可复算每只的 MAE 序列；④ 追加写（INSERT-ONLY 语义），可归档、不可改。
- **来源**：§A2、§A5-5。

### B 组 · 预测开口日覆盖更多（对应解剖 §B）

#### R2-06 · C 档 7 只走前验证批次（C→B）
- **优先级**：P0
- **场景**：用户问「22 只里为什么只有 15 只有预测」。
- **痛点**：C 档 7 只（025500/018957/021528/457001/021662/163208 + 022485）代理映射置信度未验证——**非行情缺失**（457001/163208 代理日线缓存有 320 根），预测入口只放行 A/B（§B2）。
- **需求**：对 C 档 7 只逐一跑六窗走前验证（**lift≥1.0 且 Δ≥0 即升 B**），出结论：升 B / 维持 C 附原因 / 降 D 附原因；升 B 即进入预测 universe；验证复用 21-factor-governance 既有机制（零新数据需求）。
- **验收**：① **7/7 出验证结论**（硬指标）；② 预测覆盖 15/22 → **按实计 =（15+升 B 只数）/22**（全升 B 即 22/22，为目标值而非承诺，§7）；③ 升 B 的资产 60 个交易日内至少 1 条台账记录，或注明「低频未触发」（非故障）；④ 验证证据（六窗 lift/独立触发日/Δ）可复核。
- **来源**：§B3-1、§B4-1。

#### R2-07 · 影子盘按现档位重算
- **优先级**：P1
- **场景**：用户翻台账发现 022485 有 20 行 gray 记录，但它现在是 C 档。
- **痛点**：台账口径随 holdings 档位漂移，未做一致性重算（§B2 历史遗留）。
- **需求**：滚动影子盘按**现档位**幂等重算（rolling_shadow_backfill 幂等重跑），口径与当前 tier 一致。
- **验收**：① 重算后「台账记录档位 vs 当前持仓档位」一致性检查 **0 冲突**；② 重算幂等（重复执行结果不变，可断言）；③ INSERT-ONLY 纪律不破（重算=按当前口径重生成滚动窗，旧记录归档保留）。
- **来源**：§B2、§B4-2。

#### R2-08 · 开口低频期望管理（月度口径）
- **优先级**：P1
- **场景**：用户连续多日打开信号页只有「今日无信号」。
- **痛点**：把事件低频（E1/E3 是低频事件门）误读为系统故障（§B4-3）。
- **需求**：空态文案含四要素 + 低频基线说明；验收口径由「日开口数」改为「**滚动 20 交易日开口资产数**」。
- **验收**：① 空态含 监控中 N/M、距上次开口 N 个交易日、上次开口、上次结果 四要素；② 文案含「20 交易日约 11 资产开口，多数交易日不开口是常态」级别说明；③ 滚动 20 交易日开口资产数 **不低于基线 11**；④ C 档升 B 后 60 交易日内开口资产-日累计 **≥42**（基线 32 × 1.3）。
- **来源**：§B4-3、§B1。

#### R2-09 · QDII 领先口径明示
- **优先级**：P1
- **场景**：用户看到 QDII 信号，不知道境内代理领先净值意味着什么。
- **需求**：信号卡与持仓 QDII 行标注「境内代理领先净值 1–2 天」（纯文案层，无机制变更）。
- **验收**：① 3 只 QDII 代理（024239/457001/021662 等）信号卡出现标注；② 口径与 Brief §5.3 一致；③ 不改变任何信号逻辑（可断言）。
- **来源**：§B4-4。

#### R2-10 · 出口灵敏度研究项（不动冻结参数）
- **优先级**：P2
- **场景**：用户问「为什么 32 次开口只有 4 次（12.5%）过出口」。
- **痛点**：BAND=0.02 是冻结参数，直接调参违反 §5.2 方法论（§B4-5、§B3-3）。
- **需求**：以**研究性质**评估 BAND 0.02→0.01 与 KLOW2/拥挤度分位微调的走前 Δ，产出进 21-factor-governance；**R2 内不改动任何冻结参数**。
- **验收**：① 研究报告落盘（走前 CV 六窗 + placebo）；② 报告若建议改参，附「重走六关」提案且 R2 内不执行（可断言 frozen_params 无 diff）；③ 研究不阻塞主链交付。
- **来源**：§B4-5；Brief §5.2。

### C 组 · 分析准确率更高（对应解剖 §C）

#### R2-11 · 回测接通复盘页（清硬编码 + 口径同页）
- **优先级**：P0
- **场景**：用户打开复盘页，hero 与三窗口表全是「—」，系统看起来像半成品。
- **痛点**：/review/scores 硬编码全 null（app.py:498-514）；回测机制齐备（factor_engine.evaluate 六窗）但出口未接（§C1/§C2）。
- **需求**：把生产配置作为 builtin 因子跑 evaluate（六窗 lift/Δ + bootstrap），回填 /review/scores 的 hero 与三窗口行（data_kind=backtest）；同页展示口径（走前 CV、purge=H+2、placebo≥2pp、holdout 60）；未接通窗口保持「待填充」，**不填估计值**。
- **验收**：① hit_rate/baseline/delta 由**全 null → 至少 T+1 窗口非 null**；② 页面出现「命中率 / 基线 / Δ / 开口数」且 Δ 可复算（同数据同口径结果一致）；③ 口径声明与 backend cv-config 一致；④ T+3/T+15 未接通显示「待填充」（负向断言：不得出现估计值）；⑤ 回测与实盘视觉/文案可区分；⑥ 代码中不再有「硬编码 null」出口（grep 验证）。
- **来源**：§C1、§C2-2、§C3-1、§C3-5。

#### R2-12 · 台账自动回填 t1_real
- **优先级**：P0
- **场景**：用户想事后核对某条信号赢没赢。
- **痛点**：backfill.jsonl **0 行**；320 条台账零 t1_real；逐笔对账全「待回填」（§C1）。
- **需求**：到期信号按代理日线自动回填 t1_real（写**独立** backfill.jsonl，INSERT-ONLY 语义），逐笔对账与时间线出 hit/miss。
- **验收**：① backfill.jsonl 由 **0 行 → ≥1 条真实回填**（R1 retro 行动项成功判据）；② 已到期 up 信号回填覆盖率 **100%（4/4 及以上）**；③ 回填只写 `t*_real`、不动 signal；④ **可复算**：给定代理日线可复现 hit/miss；⑤ 回填口径（代理涨跌 vs 净值涨跌）页面注明且全站一致（口径选择待 S2 裁定）。
- **来源**：§C1、§C3-2；`retro.md` 行动项 1。

#### R2-13 · 解开 20/60 结构矛盾（进度真实化）
- **优先级**：P0
- **场景**：引擎页「连续记录进度 0/60」永远走不满。
- **痛点**：SHADOW_WINDOW_DAYS=20 滚动裁剪 vs TARGET_DAYS=60 达标要求 → consecutive_days **封顶 20，qualified 永不可达**（§C1 结构性缺陷）。
- **需求**：连续记录天数改按「**归档 + 主文件**」合并计算（archive 已全量留痕，只差 shadow_progress 读 archive），或调整保留策略；UI 进度条显示真实 x/60。
- **验收**：① 连续记录天数**可达 ≥60**（归档合并计算的可达性证实，或真实数据走满）；② 引擎页进度条与后端 shadow_progress 一致（不再封顶 20）；③ 说明标注「归档合并计算」口径；④ QA 增补「裁剪后归档可完整重建窗口外记录」回归用例。
- **来源**：§C1、§C3-3、§E6-3。

### 7. 覆盖口径决策（15/22 与 C 档 7 只如何写入验收）★

   - **硬指标（承诺）**：7 只**全部出验证结论**——升 B（lift≥1.0 且 Δ≥0）/ 维持 C（附原因与复查日）/ 降 D（附原因）；
