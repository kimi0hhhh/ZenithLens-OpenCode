### 1. 会签收敛纪要（D-1..D-4 / R-1..R-5 / N-1..N-4）

#### 1.1 D-1 · 官方档零误差混入 vsum 分档与加权 MAE（实质分歧 · 部分采纳）
- **PM 立场**：官方档已发布时误差≈0（既成事实），混入分档与加权 MAE 会**制度性稀释** vsum；要求：官方档单列 chip、vsum 主指标改「估算档」；tooltip 措辞采纳（两行 + 「既成事实」入字典）；不修订则终验按「vsum 数字不代表估算质量」标 CONCERN。
- **架构立场**：**部分采纳**。认同「估算质量 ≠ 既成事实」不能混算（原设计确实把零误差官方样本计入了全档加权）；但不接受「删除式拆分」——官方档的徽章置信度是**单基金级信息**（且未发布时段 `nav_date<D` 的官方锚有真实误差），全档口径应以「参考」保留而非剔除。
- **最终结论**：
  1. vsum 主指标 = `estimate_quality.weighted_mae_rate`（估算档 intraday/holdings/proxy）；
  2. 官方档单列 chip = `official_summary.{count, market_value, weight_ratio}`；
  3. 全档 `weighted_mae_rate` 登记为「**全档参考**」，保留展示但不得再作主指标；
  4. tooltip 双行措辞采纳；「既成事实」入文案字典（R2-25）。
- **影响工件**：09 v9.1 §4.5/§9.1（新增 2 对象 + M3 语义登记）；07 v3.1 §2.2；03-ui-v3/frontend-dev 同步。
- **双向让步**：架构接受主指标拆分（承认原设计混算）；PM 接受官方档徽章保留 + 全档参考并列（放弃删除式主张）。

#### 1.2 D-2 · 9/9 收口超窗风险 + 证据来源缺位（实质分歧 · 全部采纳）
- **PM 立场**：70 原排期把「防小样本」错绑在「等待展示通道」上——展示通道样本自 R2 上线逐日积累（n≥20 ≈4 周、40 可配对日 ≈8 周），9/9 结论有不可达风险；且 v1 口径退役后，复核赖以判断的「方向命中率 ≥60%」**无指定数据来源**。要求：(a) 增设代理质量重建证据道（bars×nav 史）；(b) G2-01 双时点成文（首判 5 / 终判 40）；(c) 收口 ≤ G-PM-05，超窗联合延期说明。
- **架构立场**：**全部采纳**。技术判断成立：`build_accuracy` v2 的样本来自展示入账记录（现状仅 1 天）；v1 公式在 R2-16 净值史就绪后**立即可重建**（bars 缓存 320 根已备）；「代理质量」与「展示精度」是两类问题——原排期误诊为「证据不足」，实为「证据源选错」。原设计亦缺显式时点（5 日/40 日模糊）。
- **最终结论**：
  (a) 新增 **代理质量重建证据道**：`data/snapshot/proxy_quality.json`（v1 公式、40 日窗、重建式）；R2-04 与换代理筛选**首选证据**；与展示通道**分键分文件**（防两口径混用）。
  (b) **双时点**：首判 = 满 5 个可配对日（`window_phase=first_verdict`，全档首出值）；终判 = 满 40 个可配对日（`mature`）。
  (c) **收口硬约束**：9/9 结论不晚于 G-PM-05 终验；超窗 → PM×架构联合延期说明；未收口资产按 §2.4 层①挂档（带复查日与样本量），否则按未完成计。
- **影响工件**：08 v3.1 §3.1b/§4.4/§7.4；09 v9.1 §4.5/§6.1（`window_phase`）；06 v3.1 §3（`proxy_quality.json`）；PM 侧 `19-pm-acceptance` 终验红线。
- **双向让步**：架构承认排期诊断错误并重设证据源与排序；PM 接受展示通道继续作为**徽章成熟度指标**（不废弃，但不得作复核判据）。

#### 1.3 D-3 · 评分对象「当日最终一条」致非官方档样本饥饿（实质分歧 · 采纳）
- **PM 立场**：`ADR-0007` 的「每个 `(date,code)` 取最后一条」使 intraday/holdings 档样本只来自「当日最后一条恰为该档」的日子，归键受运行时刻扰动；极端情形 holdings 档长期凑不满 5 样本 → 置信度永远 `no_samples`，与 R2-01「每档可信度」承诺冲突。要求改「**同 mode 当日最后一条**」或给出等价防饥饿保证。
- **架构立场**：**采纳**。PM 论证成立：单归键设计把「展示收敛」误用于「评分样本」——多轮刷新应防「同 mode 同日重复计分」，但不该让不同 mode 互相挤出样本。
- **最终结论**：评分对象 = 每个 `(date, code, mode)` 的**当日最后一条**记录（同 mode 同日多轮取最后；不同 mode 各自成样本、各自归键 `mode|code`）；官方档 published 与 stale-anchor 记录均入 `official|code`（与 D-1 的主指标拆分不冲突）。
- **影响工件**：09 v9.1 §9.2-M1/§3.2；08 v3.1 §3.1（伪代码）；ADR-0007 修订。
- **双向让步**：架构修正自身设计；PM 无让步项（本项为架构单方修订）。

#### 1.4 D-4 · 挂档复查日口径冲突 + 防稀释闸缺失（实质分歧 · 全部采纳）
- **PM 立场**：(a) 两处口径打架（10 §2.4=`+30 交易日` vs 08 §4.1=`+90 自然日`，差 3 倍），「挂档≠拖」的纪律基础被架空；复查日应从**证据就绪日**起算并展示（行内 tooltip + 覆盖面板「待结论清单」）；(b) 挂档 >3 只 → 架构×PM 复审；(c) 挂档行不得计入「已验证/预测覆盖增长」、不进 universe；(d) 终验红线：「无超标且无结论、无复查日、超窗无联合延期说明」三项任一即不通过。
- **架构立场**：**全部采纳**。`+90 自然日` 与 `+30 交易日` 系两处文字事故（同一机制两个数），统一为 **+30 交易日、自证据就绪日起算**；防稀释闸与展示位置要求合理（挂档只算过程态，不算终局结论）。
- **最终结论**：复查日 `verify_review_date`（+30 交易日）与覆盖面板 `pending_verification_names` 入契约；>3 只同时挂档 → 架构×PM 复审并落纪要（视为验证批次设计异常）；挂档行不计已验证/覆盖增长、不进 universe（成文断言）；终验红线由 PM 写入 `19-pm-acceptance`。
- **影响工件**：09 v9.1 §3.1/§9.1-4/5；08 v3.1 §4.1/§4.4；07 v3.1 §2.7/§2.5（history_days 一并展示）。
- **双向让步**：架构接受防稀释与展示约束（原设计缺）；PM 接受 30 交易日机制本身（认可 ≈6 周足以跨过 n≥20 门槛）。

#### 2.4 ISSUE-ZL-R2-04 · 首测不达标「挂档 vs 降档」边界条件
- **结论（冻结，落 08 §4.4；判定函数 `review_verdict(evidence, samples)`）**：**三层顺序判定**——

| 层 | 条件（按序命中即停） | 处置 | 理由 |
|---|---|---|---|
| ① 样本门槛 | 独立触发日 <20（或 n_test<20） | **挂档观察**：档位/口径不变，标「低样本·观察」+ 复查日（**+30 交易日，自证据就绪日起算**）；不得升档、不得降档；>3 只同挂档 → 架构×PM 复审 | 小样本不可定性（pre-mortem P3）；降档须有证据 |
| ② 口径回退（估值线） | R2-03 双段不达标 / R2-02 前 20 不达标（样本足） | **回退口径**：双段→单段（`first_test_failed`）/ 前 20→前 10 + 标注；tier 不动 | 估值口径与预测 tier 是两条线，不得互相降级 |
| ③ 降档（tier 线） | 样本足且不达标：方向命中率 <60%（025857/163208/014320 类）或 lift<1.0 或 Δ<0 | **降档**：换代理重验；无合格候选 → 降 D + `tier_reason` + 移出 universe；挂档到期未改判 → 强制降档 | 不做清单 15：不用"挂着 C"冒充覆盖；挂档≠拖 |

- **一票否决（不等样本）**：代理断供/映射失效/数据不可得 → 直接回退或降档并标原因。
- **验收复算**：三层输入（独立触发日、方向命中率、MAE、lift/Δ）来自 `proxy_quality.json`（复核判据）/ `accuracy.json`（展示成熟度）/ `tier_reviews.jsonl`，可逐条复算。

#### 13.3 `qualified` / 「上线资格」语义影响（重要）
- **事实**：窗口=60 且启动即回填满 → `consecutive_days` 可达 60、`status=qualified` **立即可达**。
- **关键诚实点**：窗口内记录为**走前回算口径**（与既有 warmup/rolling 重算机制一致——在历史 bars 上按 `bars[:t-1]` 逐点走前计算），**非自然前向积累**；「连续 60 个交易日的实盘观察」原义不再由该状态单独承载。
- **影响**：若沿用原文案（"连续 60 日无漏单才具上线资格"），会造成"上线资格已达成"的误导。
- **建议表述（PM 跟踪，入文案字典）**：
  1. `qualified` 展示：「**记录窗已满 60 交易日（走前回算）**」——只陈述窗口完整度，不宣称上线资格；
  2. `note` 更新为：「窗口 60 交易日；记录按走前口径回算补全（非自然积累）；上线资格建议结合实盘观察另行评估」；
  3. `shadow_audit`（偏差 ok/bad）数据同源回算，文案相应标注；
  4. 若未来需要恢复"真机 60 日观察"语义 → 另设「实盘观察起点」跟踪（**R3 候选，本轮不新增字段**）。
- **PM 行动**：更新 R2-08 低频文案基线（60 日口径，原「20 交易日约 11 资产」失效）+ `qualified` 措辞入库；QA 负向断言「无上线资格暗示」。

#### 13.4 计算量评估（60 日 × ≈15 资产）
- **实测锚**：20 日窗全量走前重算 ≈300 次单点训练 ≈5.5s CPU（15 资产；`14-api-impl-report-r2` §10.2）。
- **60 日窗线性外推**：≈900 次训练 ≈**15–17s CPU**（启动首跑一次性）；主文件 ≈900 行、≤~0.3MB（量级可忽略）。
- **每日滚动**：窗口平移后全量重算同量级（≈15–17s）；**建议**：优先保留存在性快路径（完整窗跳过），若每日时延不可接受则评估**增量模式**（仅计算新增 1 日 × 资产数，≈15 次训练 ≈0.3s）——增量属实现优化，**不改变走前回算口径与幂等断言**。
- **冷启动**：S3 修复（快路径+解析缓存）已验证 20 日窗；窗口 ×3 后须**复测** `ready+1s/+6s` 的 `/holdings` 时延与 warmup 时间戳（沿用 S3 探针脚本）。
- **幂等性保持**：`(date,code)` 唯一跳过、`created_at` 继承、裁剪先归档后重写、recompute `reason` 不变——B-7 断言逐条保持。
