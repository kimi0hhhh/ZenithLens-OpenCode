## 补记 · 用户指令 2026-09-13（影子盘「补满 60 天 · 来一天换一天」口径）

> 本补记只追加：记录用户 2026-09-13 指令对影子盘滚动窗口的口径变更及验收影响；**与正文冲突处以本补记为准**（正文 §2C / §7.3 G-6 中「20 日滚动 / 归档合并」相关表述随之更新）。架构与字段以 `09-api-contract-r2` **v9.5**（更新中）为法律文本。

### 1. 口径变更（用户指令要义）

- 影子盘滚动窗口 **20 → 60 个交易日**；
- **启动即回填 60 个交易日（补满）**，此后**每日滚动——「来一天换一天」**（新增当日、移出最旧）；
- 生效后 `consecutive_days` 立即 ≥60，进度条显示 **60/60**。

### 2. 验收影响（诚实口径，不得夸大）

- **60/60 属「走前回算口径」**：该 60 日记录为**启动时回算生成 + 到期回填**（信号生成沿用走前纪律 `bars[:t-1]` 截断；结果由代理日线回填）——**不是**「自然前向观察 60 日」，**不是**「实盘连续记录 60 日」。任何 UI / 文档 / 交付说明**不得**表述为自然前向观察或实盘连续达标。
- **R2-13 判定：达标（回算口径）**。依据：窗口与回填扩至 60 后，「连续记录 ≥60」在启动即达成且「来一天换一天」维持日滚动，进度条与后端一致（不再封顶 20）；原「归档合并」路径退为兼容/历史实现，口径标注按 v9.5 更新。
- **R2-12 判定：达标（机制口径）**。依据：回填机制已在 S6 live 复核通过（`backfill.jsonl` 304 条、`method=proxy_bar` + `proxy_code` 100%、复算一致、只写 `t*_real`）；窗口扩至 60 后到期信号数量扩大、机制不变；执行后具体数字由 QA 随 v9.5 重算复核（属复核动作，不影响判定）。
- 与 R2-01 的关系：估值置信度通道独立，不受本口径影响（其双时点未到期状态不变）。

### 3. PM 立场与 UI 表述要求

- **立场：附条件同意**。用户指令优先、执行无异议；条件均为「诚实标注 + 可复算」，不改变机制本身。
- **硬性表述要求**：
  1. 进度及影子盘相关位置统一标注「**滚动 60 日 · 回算口径（启动回填）**」；禁止出现「自然前向观察」「实盘连续」类表述。
  2. 「上线资格」文案改述为「**60 日回算覆盖达成（启动回填口径）**」，不得暗示已通过前向验证；`shadow_audit`（偏差审查）同挂「回算口径」标签——回算命中率 vs 基线的偏差可展示，但须与前向/实盘语义分离。
  3. 可复算记录：60 日回填参数（窗口、回填起止日、tier 口径时点、生成方式）须落盘可复算；INSERT-ONLY 纪律不破（重算 = 先归档后重生成，以 v9.5 为准）。
  4. QA 补回归：60 日滚动「来一天换一天」幂等、裁剪与回填边界、旧口径标注零残留（含 07-r2 / 03-ui-v3 / 线框同步）。
